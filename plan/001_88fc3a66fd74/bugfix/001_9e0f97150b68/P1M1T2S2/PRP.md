# PRP — P1.M1.T2.S2 (bugfix 001_9e0f97150b68): Shipped-dict calibration test + prose no-menu e2e gate

---

## Goal

**Feature Goal**: Make BUG-001 permanently un-regressable. Add (a) a
calibration block to `test/shipped-dict.test.ts` asserting the shipped
`dict/common-en.bin` returns `lookup(w) >= REJECT_COMMON_THRESHOLD` for the
top common English words (constants IMPORTED from `src/core/score.ts` —
never hard-coded), and (b) an end-to-end no-menu gate: ingest
`test/fixtures/sessions/prose.jsonl` through a real `IngestPipeline` with
the shipped dict and assert `getSuggestions` for common words (`with`,
`this`, `them`, …) yields **no hapax word items** (delegation, not a menu).
Also broaden acceptance item 2's probe list with ≥4-char common words so the
gate can never again be masked by the shape gate's length rule.

**Deliverable**:
- Extended `test/shipped-dict.test.ts` (calibration block)
- New `test/calibration.test.ts` (e2e prose no-menu gate)
- Broadened PROBES in `test/acceptance.test.ts` item 2 (+ updated comments)

**Success Definition**: `npm test` / `npm run check` green; deleting or
mis-calibrating `dict/common-en.bin`, or retuning the band constants past
the calibration words, makes the suite FAIL; P1.M5.T1.S1's typing-path
probes consume these gates.

## Why

- BUG-001 (Critical): the old artifact admitted every common word as rare;
  typing "with"/"this"/"them" popped menus during ordinary prose — the #1
  UX invariant (§01/§07 "never trigger a menu for common words") was broken
  end-to-end.
- The scripted acceptance item 2 masked this because all 22 of its probe
  words were ≤3 chars — the shape gate rejects those by length regardless of
  dictionary calibration. A gate that can't see the failure is worse than no
  gate; this task closes both the calibration assertion and the probe blind
  spot.
- Recalibrated constants (P1.M1.T2.S1) and the regenerated artifact
  (P1.M1.T1.S2) land before this item — but nothing currently PINS them.
  Without this test, a future artifact regen or "harmless" constant tweak
  silently reintroduces BUG-001.

## What

1. **Calibration block** in `test/shipped-dict.test.ts`: for
   `['the','with','this','them','that','have','would']` assert
   `dict.lookup(w)! >= REJECT_COMMON_THRESHOLD`; `'qqqqzzzz'` → `null`.
2. **e2e no-menu gate** in new `test/calibration.test.ts`: ingest
   `prose.jsonl` through a real `IngestPipeline` (shipped dict), then for
   `with`/`this`/`them` assert the provider **delegates** (returns the
   delegate sentinel) — no menu item whose value lower-cases to the typed
   word. For `thin`/`firs`: measure actual behavior first, then pin it with
   a comment documenting the measurement ('first'-adjacent suggestions are
   legitimate ONLY if 'first' itself is not rejected; with the recalibrated
   bands it should be — verify, don't assume).
3. **Broaden acceptance item 2**: add ≥4-char common words to PROBES and
   update the describe's explanatory comment (which currently says band
   calibration is "NOT asserted here" — now it is, elsewhere; fix that text).

## Anti-Patterns to Avoid

- ❌ Hard-coding 220/120 (or the new values) anywhere in tests — import the
  constants or the gate decays on the next retune
- ❌ Adding ≥4-char probes without measuring zero-candidates first — a
  probe matching a rare prose prefix breaks the suite or, worse, weakens
  the assertion to tautology
- ❌ Asserting only `rankMatches === []` — the BUG-001 failure was visible
  only through the full provider path; keep the provider delegation e2e
- ❌ Deleting/weakening the 'wate'→'Water' positive control because it's
  inconvenient — it proves a non-empty, functioning store
- ❌ Modifying score.ts constants or the dict artifact from this task
- ❌ Refactoring acceptance.test.ts helpers beyond what the probe addition
  needs (minimal-diff discipline in a 400+ line passing suite)
